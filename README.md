# כיתה של סוכנים

אפליקציית ווב קטנה: צ'אט לימוד עם כמה "דמויות" וירטואליות (מורה + 2 סוכנים מתחלפים + קאמיאו נדיר), לפי התכנון שגובש בשיחה.

## הרכב הסוכנים

- **המורה** — קבוע, מקור האמת. כל תשובה שלו עוברת שכבת אימות עובדתית שקטה (מודל זול/מהיר) לפני שהיא מוצגת; אם נמצאת טעות, המורה מתקן ומנסה שוב (עד 2 פעמים).
- **מאגר רוטציה** — דני (תלמיד טועה-לפעמים), המעמיק, השטוח, המקשר. בכל שיעור נבחרים 2 מתוך 4, לפי הנושא:
  - נושא טכני/מדויק (מתמטיקה, פיזיקה, קוד...) → המעמיק + השטוח.
  - נושא נרטיבי/מושגי (היסטוריה, ערכים, ספרות...) → דני + המקשר.
  - נושא אחר → נבחרים אקראית.
- **הבדחן** — קאמיאו, מצטרף רק מדי 3-4 סבבים.

כל סבב: המורה מגיב (מאומת), ואחד משני סוכני המאגר מגיב בתורו (רוטציה), ובסבבים נדירים גם הבדחן. התגובות **מוזרמות** (streaming) — הטקסט מופיע בזמן אמת תוך כדי שהמודל "כותב", לא מחכים לתשובה שלמה (ראו "תגובות בזמן אמת" למטה).

במסך ההתחלה ניתן לבחור ידנית אילו 2 "תלמידים" מתוך 4 משתתפים בשיעור (עם אווטאר צבעוני לכל דמות), או להשאיר ללא בחירה ולתת למערכת לבחור אוטומטית לפי הנושא.

## תגובות בזמן אמת (streaming)

במקום לחכות שתגובה שלמה תיבנה בשרת ואז לקבל אותה בבת אחת, הטקסט מוזרם בזמן אמת דרך Server-Sent Events (`POST /api/message/stream`):

- **המורה** — מחייב אימות עובדתי לפני שמשהו מוצג (אי אפשר "לבטל" טקסט שכבר הוזרם למשתמש אם הוא התגלה כשגוי), אז התשובה נבנית ומאומתת מאחורי הקלעים כרגיל, ורק אז "מוזרמת" החוצה מילה-מילה — זו עדיין הזרמה אמיתית ברשת (לא טריק ויזואלי בצד הדפדפן), רק לא הזרמת-טוקנים חיה מהמודל.
- **כל שאר הדמויות** (דני/מעמיק/שטוח/מקשר/בדחן) — הזרמת טוקנים חיה ישירות מ-Claude, בלי שלב ביניים.

אם מתרחשת שגיאה (מפתח חסר/שגוי, תקלת רשת) היא מגיעה כאירוע `error` בתוך הזרם עצמו, כי ברגע שההזרמה התחילה כבר אי אפשר לשנות את קוד הסטטוס של התגובה.

## בוחן בסוף שיעור

כפתור **"📝 בוחן על השיעור"** (בפס הנושא, אחרי שהתחיל שיעור) מייצר 4 שאלות אמריקאיות על בסיס **כל** מה שבאמת נדון בשיחה הספציפית הזו (לא טריוויה כללית על הנושא) — קריאת API נפרדת, לא אחת מהדמויות בכיתה. אחרי הגשה מוצגים ציון, סימון תשובה נכונה/שגויה, והסבר קצר לכל שאלה.

דורש לפחות הודעה אחת בשיחה (אי אפשר לבנות בוחן על שיעור ריק), ומשתמש באותו מפתח API אישי כמו שאר הצ'אט.

## מפתח API אישי (BYOK — חובה)

**השרת לא מחזיק מפתח API משותף לצ'אט הווב.** כל משתמש חייב להזין **מפתח Anthropic (Claude) אישי משלו** דרך כפתור ה-🔑 (למעלה-שמאל) לפני שהוא יכול להתחיל שיעור — בלי מפתח, כפתור "התחל שיעור" מושבת והחלון נפתח אוטומטית.

המפתח:
- נשמר **רק בדפדפן** (`localStorage`), לעולם לא נשמר ב-DB או בלוגים של השרת.
- נשלח לשרת רק כ-header (`X-Anthropic-Key`) בכל קריאה, ומשמש לבניית לקוח Anthropic חד-פעמי לאותה קריאה בלבד — לא נשמר בזיכרון מעבר לכך.
- בקשה בלי מפתח (או עם מפתח לא תקין) נדחית עם שגיאה ברורה (401) במקום להשתמש במפתח "חינמי" כלשהו.

אפשר ליצור מפתח ב-[console.anthropic.com/settings/keys](https://console.anthropic.com/settings/keys).

**גם ב-Slack:** אין שם מפתח משותף/כללי לבוט — כל משתמש ב-Slack מגדיר את המפתח האישי שלו בעצמו עם הפקודה `/classroom-key sk-ant-...` (נשמר בזיכרון השרת בלבד, לא ב-DB). ראו "אינטגרציית Slack" למטה.

## כניסת משתמשים (Google Login)

כפתור **"התחברות עם Google"** (למעלה-ימין) מאפשר למשתמש להתחבר עם חשבון Google ולראות את השם/תמונה שלו באתר. זו **זהות בלבד** — לא קשורה למפתח ה-API (שממשיך להיות תמיד בדפדפן, גם למשתמש מחובר וגם לאורח). אם ההתחברות לא מוגדרת בשרת (חסרים המשתנים למטה), הכפתור פשוט לא מופיע והאתר ממשיך לעבוד כרגיל בלי צורך בהתחברות.

### הגדרה ב-Google Cloud Console
1. גלוש ל-https://console.cloud.google.com/apis/credentials וצור פרויקט (אם אין לך).
2. **OAuth consent screen** → הגדר אפליקציה (External, אם זה לא Workspace פנימי) עם שם ואימייל תמיכה.
3. **Credentials** → **Create Credentials** → **OAuth client ID** → Application type: **Web application**.
4. תחת **Authorized redirect URIs** הוסף: `https://<הכתובת-שלך-ב-Render>/auth/google/callback`
5. אחרי היצירה תקבל **Client ID** ו-**Client Secret**.

### משתני סביבה נדרשים
- `GOOGLE_CLIENT_ID`
- `GOOGLE_CLIENT_SECRET`
- `SESSION_SECRET` — נוצר אוטומטית על ידי `render.yaml` (`generateValue: true`), אין צורך להזין ידנית.

את שני משתני ה-Google יש להזין ידנית ב-Render (Environment), בדיוק כמו משתני ה-Slack.

## המשך שיעורים קודמים

במסך ההתחלה מופיע **"שיעורים אחרונים"** — רשימה שנשמרת מקומית בדפדפן (localStorage), כך שאפשר לחזור ולהמשיך שיעור שהתחלת קודם (גם בלי התחברות). אם אתה מחובר עם Google, מתווספת גם רשימת **"השיעורים שלי"** שנשמרת בשרת (DB) ונגישה מכל מכשיר שבו אתה מתחבר לאותו חשבון.

לחיצה על שיעור טוענת את כל ההיסטוריה שלו (ללא השמעה קולית חוזרת של הודעות ישנות) וממשיכה את השיחה בדיוק מאיפה שהפסיקה — כולל זיכרון הדמות שהייתה בתור הבא, וספירת הסבבים לקאמיאו של הבדחן.

הערה: שיעור שנוצר כש-`DATABASE_URL` לא מוגדר קיים רק בזיכרון השרת, ונעלם בריסטרט — אין מה לשחזר.

## הפעלה מקומית

```bash
cd backend
pip install -r requirements.txt
uvicorn main:app --host 0.0.0.0 --port 8000
```

ואז לפתוח בדפדפן: `http://localhost:8000` — ותזין מפתח Anthropic אישי דרך כפתור ה-🔑 (אין יותר `ANTHROPIC_API_KEY` כללי לצ'אט הווב, ראו "מפתח API אישי" למעלה).

### משתני סביבה אופציונליים
- `CLASSROOM_MODEL` — מודל לדמויות (ברירת מחדל: `claude-sonnet-5-5`)
- `CLASSROOM_VERIFIER_MODEL` — מודל לשכבת האימות השקטה (ברירת מחדל: `claude-haiku-5-5`)

## מבנה הפרויקט
```
backend/
  agents.py        # הגדרות הדמויות (system prompts)
  orchestrator.py  # state machine: בחירת מאגר, אימות מורה, סדר תגובות
  db.py            # התמדה אופציונלית ל-Postgres (שיעורים + הודעות)
  main.py          # FastAPI, מגיש גם את ה-frontend
  slack_bot.py      # אינטגרציית Slack (אופציונלי)
frontend/
  index.html       # צ'אט + מיקרופון (Web Speech API)
```

## התמדה (DB)

השיחות נשמרות כעת ב-**Postgres** (אם מוגדר `DATABASE_URL`) ולא רק ב-memory — כך שיעור לא נמחק בריסטרט/שינה של השרת. אם `DATABASE_URL` לא מוגדר (למשל בהרצה מקומית בלי DB), הקוד עובד בדיוק כמו קודם, רק בלי התמדה.

`render.yaml` מגדיר `databases:` עם Postgres בתוכנית החינמית ומחבר אותו אוטומטית ל-`DATABASE_URL` של השירות — Render Blueprint sync ייצור את מסד הנתונים אוטומטית בפעם הראשונה שתדחוף את השינוי הזה (או שתסנכרן Blueprint ידנית בממשק).

הערה: Postgres החינמי של Render פג תוקף אחרי 90 יום (מגבלת Render), ואז צריך ליצור מסד חדש.

## מה עוד שווה להוסיף בהמשך
- לוגיקת רלוונטיות חכמה יותר לבחירת מי מהמאגר מגיב בכל סבב (כרגע רוטציה פשוטה).
- הגבלת אורך תשובות אגרסיבית יותר (post-processing) אם סוכן "נשבר" מהכללים.
- מסך "שיעורים קודמים" שמציג היסטוריה מה-DB.

## פריסה חינמית ל-Render

הפרויקט כולל `render.yaml` (Blueprint) בשורש, כך ש-Render מגדיר הכל אוטומטית.

1. היכנס ל-https://render.com והתחבר עם GitHub.
2. New → Blueprint → בחר את ה-repo `classroom-agents`.
3. Render יזהה את `render.yaml` ויציע ליצור שירות `classroom-agents` בתוכנית Free.
4. אין צורך להזין שום מפתח API כללי — גם הווב וגם Slack עובדים ב-BYOK בלבד, כל משתמש מכניס את המפתח שלו (ראו "אינטגרציית Slack" למטה).
5. אשר את ה-Deploy. בתוך כמה דקות תקבל כתובת ציבורית כמו `https://classroom-agents.onrender.com`.

הערה: בתוכנית החינמית השירות "נרדם" אחרי זמן ללא תנועה, והבקשה הראשונה אחרי שינה עלולה לקחת כ-30-60 שניות.

## אינטגרציית Slack (אופציונלי)

ניתן לדבר עם הכיתה גם מתוך ערוץ Slack, בנוסף (או במקום) לאתר. כל ערוץ/DM מנהל שיעור אחד בכל פעם; כל דמות מפרסמת הודעה נפרדת עם שם ואימוג'י משלה.

### יצירת Slack App
1. היכנס ל-https://api.slack.com/apps → **Create New App** → **From scratch**.
2. בחר שם (למשל "כיתה של סוכנים") ואת ה-workspace שלך.
3. **OAuth & Permissions** → תחת **Bot Token Scopes** הוסף: `chat:write`, `commands`, `channels:history` (ולערוצים פרטיים גם `groups:history`), ו-`im:history` אם תרצה גם ב-DM.
4. **Install App to Workspace**, ואז העתק את ה-**Bot User OAuth Token** (מתחיל ב-`xoxb-...`).
5. **Basic Information** → **App Credentials** → העתק את ה-**Signing Secret**.
6. **Slash Commands** → **Create New Command** (צריך ליצור **שתיים**):
   - Command: `/classroom`, Request URL: `https://<הכתובת-שלך-ב-Render>/slack/commands`, Description: "התחל שיעור חדש"
   - Command: `/classroom-key`, Request URL: `https://<הכתובת-שלך-ב-Render>/slack/commands`, Description: "הגדר מפתח API אישי"
7. **Event Subscriptions** → הפעל (Enable Events):
   - Request URL: `https://<הכתובת-שלך-ב-Render>/slack/events` (Slack ישלח אימות אוטומטי — ה-endpoint כבר תומך בזה).
   - תחת **Subscribe to bot events** הוסף: `message.channels` (ולפי הצורך גם `message.groups`, `message.im`, `app_mention`).
8. הוסף את הבוט לערוץ הרצוי (`/invite @שם-הבוט`).

### משתני סביבה נדרשים
- `SLACK_BOT_TOKEN` — ה-`xoxb-...` משלב 4.
- `SLACK_SIGNING_SECRET` — משלב 5.

מוגדרים ב-`render.yaml` עם `sync: false`, כך שצריך להזין אותם ידנית בממשק Render (Environment). **אין** משתנה מפתח API משותף ל-Slack — בדיוק כמו באתר, כל משתמש ב-Slack מכניס מפתח אישי משלו (ראו למטה).

### שימוש
1. `/classroom-key sk-ant-...` — **כל משתמש** שרוצה להשתתף מגדיר פעם אחת את מפתח ה-Anthropic האישי שלו (נשמר רק בזיכרון הזמני של השרת, לא ב-DB; נמחק בכל ריסטרט, בדיוק כמו מחיקת localStorage בדפדפן).
2. `/classroom <נושא>` בערוץ — מתחיל שיעור חדש (בוחר אוטומטית הרכב מאגר לפי הנושא).
3. כל הודעה רגילה בערוץ לאחר מכן נחשבת כשאלה/תשובה של המשתמש ששלח אותה — ונעשית עם **המפתח האישי שלו**. משתמש שלא הגדיר מפתח יקבל בקשה לעשות זאת לפני שהבוט יענה לו.
